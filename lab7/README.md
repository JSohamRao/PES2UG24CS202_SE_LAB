## Validation policy adopted for this lab

The starter and handout do not specify a complete input/error contract. The
following policy is authored for this solution, rather than attributed to the
instructor:

- Public functions accept strings of at most 4096 characters. Non-strings,
  oversize data, empty input, and invalid data return `None`. There is no
  catch-all exception handler or silent removal of bad tokens.
- A seat is one ASCII row letter A-Z followed by a positive integer. Outer
  whitespace, lowercase row letters, and leading zeros are accepted. The
  result is an uppercase row and an integer seat number.
- Prices are one or more comma-separated nonnegative ASCII integer amounts.
  Whitespace around each token is allowed. An empty or invalid token rejects
  the entire input. GST is exactly 18 percent before converting the result to
  the original float return type. Values too large for a finite float are
  rejected. This preserves integer prices, rather than adding decimal prices
  that the starter did not support.
- Ratings are one or more whitespace-separated ASCII integers from 1 to 5.
  The result is rounded to one decimal place. Empty lists and out-of-range
  ratings are rejected.
- The CLI reports invalid input and continues through all three prompts.
  EOF or keyboard cancellation ends the interaction cleanly.

These limits and domain rules are explicit implementation choices. Complete
fuzz coverage of all possible Python objects or all input strings is not
claimed; the generated tests exercise Unicode strings, `None`, other ordinary
data types, valid domains, and malformed boundaries.

## Reproduce

From this `lab7` folder in PowerShell, using Python 3.10 or newer (verified
with Python 3.12):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe movie_tickets.py
.\.venv\Scripts\python.exe -m pytest -q test_movie_tickets.py
.\.venv\Scripts\python.exe -m pytest -q --hypothesis-show-statistics test_movie_tickets.py
```

Hypothesis is configured with `max_examples=300`, `derandomize=True`, no example
database, and no timing deadline. Examples remain generated by Hypothesis;
the deterministic settings make this pinned environment easier to reproduce.
